Coverage gaps

An image that fails to scan reports no vulnerabilities, which everywhere else on this page is indistinguishable from an image with nothing wrong with it. These are the places where a zero is not evidence.

What to fix — configuration

Kubescape controls that are failing, most-affected first, each with the workloads it lands on. Control names and remediation are upstream Kubescape's own text, not ours. A count is failing workloads, so one Deployment can appear under several controls.

What to fix — policy

Audit, not enforcement. Kyverno reports these and admits the resource anyway. Its webhooks are also fail-open, so if Kyverno is unavailable the API server proceeds rather than blocking deployments.

CVE counts are deliberately not graded. They are dominated by inherited base-image CVEs rather than anything written here, so they sit beside posture instead of being folded into one score. A grade that is permanently red stops being read.

Platform namespaces are counted separately. kube-system components legitimately need hostPath, hostNetwork and privileged mode, so their policy violations are not mixed in with work anyone is going to do.

The score is computed here, and so is its history. Nothing in the cluster stores either. Kubescape’s operator writes findings; the score you see in its CLI is calculated by the client, so the collector reimplements the upstream formula — a control that passes scores 100, otherwise passed/all, and the cluster score is the plain mean across controls, unweighted by severity. That plain mean is why a movement can be attributed exactly: each control carries 1/N of the score, so the per-control changes sum to the total. Because the storage API overwrites every summary in place on each scan, history exists only because each run appends a point to a ConfigMap. The score is taken over the workloads this scan-only profile collects, so it will not match kubescape scan run from a laptop, which also evaluates host- and cluster-level controls. It is consistent with itself, which is what a trend needs.

Collection. Kyverno PolicyReports are ordinary cluster resources and list cleanly. Kubescape summaries come from an aggregated API whose LIST returns every figure as zero — only a GET of each object carries real numbers, so the collector fetches them one at a time through a local API proxy.
